# 电子靶时钟校验服务

校验射击电子靶时钟与数据顺序，定位对正式成绩的影响，为裁判提供逐发复核清单，
为技术代表提供"正式成绩采用了有效时间基准"的可归档声明。

## 业务事实

- 女子十米气步枪资格赛产生新的亚洲纪录成绩
- 资格赛成绩决定后续晋级
- 纪录发布需要依赖正式竞赛规则与设备数据
- 设备时钟漂移或重传顺序错误，可能把合法成绩误判为超时或补射

## 协作角色

- 运动员
- 电子靶系统
- 裁判与技术官员
- 纪录认证人员

## 服务流程

- **赛前巡检**：按规则文件中的巡检计划逐项检查靶机固件批准清单、校准源登记、
  赛前基准偏差、时钟连续性与未闭环事件；不合格靶位自动隔离、禁止投入使用。
- **赛中实时监测**：逐次同步采样评估绝对偏差与漂移速率，预警/严重两级告警；
  偏差越界或人工复位时系统自动隔离靶位。**恢复使用必须由技术官员确认**，
  系统不会自行恢复。
- **离线重传排序**：网络中断期间本地缓存的命中报文按设备时间重建顺序，
  标记乱序、补传与重复报文；重复报文只在视图中去重，原始报文一条不丢。
- **赛后影响报告**：逐发判定时间基准（有效 / 待复核 / 无效），输出复核清单、
  各靶位影响范围、隔离恢复台账与纪录时间基准声明，并做闭环检查。

## 不可变原则

- 每条成绩事件同时保留 `device_time`（设备时间）与 `received_time`（接收时间）。
- 领域模型为只读冻结对象，服务全程不提供修改原始命中的入口。
- 隔离台账只追加隔离与恢复事实；自动隔离无需人工介入，恢复必须有官员署名。

## 目录说明

- `contracts/domain.schema.json`：共享领域资料字段与基本约束。
- `contracts/clock_service.schema.json`：规则、靶机、遥测、申报四份数据的契约。
- `fixtures/context.json`：不含真实个人信息的公开领域样例。
- `fixtures/rules.json`、`targets.json`、`telemetry.json`、`claims.json`：
  赛事规则限值、靶机固件/校准登记、同步样本/中断/复位/成绩事件、纪录申报。
- `fixtures/build_fixtures.py`：确定性样例生成脚本，可重复执行。
- `src/records.py`：领域资料读取与基础校验。
- `src/model.py`：规则、靶机、同步样本、事件登记、成绩事件等只读模型。
- `src/inspection.py`：赛前巡检计划与赛后闭环检查。
- `src/drift.py`：偏差分级、漂移速率与实时告警。
- `src/quarantine.py`：只追加的隔离/恢复台账。
- `src/reorder.py`：离线重传重建视图（排序、去重、缺号/冲突检测）。
- `src/timebasis.py`：逐发时间基准判定。
- `src/impact.py`：影响范围报告、复核清单与纪录认证声明。
- `src/service.py`：赛前/赛中/赛后编排与中文报告入口。

## 样例场景

- `A-01`：时钟全程健康，60 发合计 630.6 的纪录申报获时间基准认证。
- `A-02`：漂移越界自动隔离，随后网络中断、离线缓存乱序补传并夹带重复报文，
  技术官员重新校准并确认恢复；隔离窗口内 6 发全部列入复核。
- `A-03`：人工复位后未及时同步被隔离，重新同步经官员确认后恢复，中间 1 发待复核。
- `A-04`：固件未批准、校准未登记且存在时钟跳变，赛前巡检不合格，全程禁止使用。

## 本地检查

```bash
python -m unittest discover -s tests   # 全部 24 项测试
python -m src.service                  # 输出赛前/赛中/赛后中文报告
python fixtures/build_fixtures.py      # 重新生成确定性样例
```

样例中不包含账号、密钥或连接凭据。
